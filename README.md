# Cardlab — Vercel

Готовый проект для Vercel: прежний интерфейс на английском, генерация и проверка формата в браузере, Stripe Checkout в тестовом режиме на сервере. Интерфейс и стили сохранены.

## Какие файлы загружать

Распакуйте `cardlab-vercel.zip`. Загрузите **всё содержимое архива в корень отдельного репозитория GitHub**, сохраняя папки:

```text
public/          HTML, стили, JavaScript, иконка
api/stripe/      серверные функции Vercel: config, checkout, session
server/          обработка Stripe и подписанная сессия браузера
scripts/         локальный запуск
test/            автоматические проверки
package.json
vercel.json
.gitignore
.vercelignore
.env.example     пустой образец, без ключа
README.md
```

Не загружайте только HTML, только `public/` или старую папку `dist/`: для Stripe требуются `api/`, `server/` и конфигурация. Файл `.env` с вашим ключом не включён в архив и не должен попадать в GitHub.

## Настройка Vercel

1. Откройте Vercel → **Add New → Project** и импортируйте этот GitHub-репозиторий.
2. **Root Directory**: корень, где находится `vercel.json`. **Framework Preset**: `Other`. **Build Command**: пусто. **Output Directory**: `public`. Конфигурация уже задаёт эти значения; сборка не нужна. Node.js: **24.x**.
3. В **Environment Variables** добавьте переменную типа **Secret**:

   ```text
   Name:  STRIPE_TEST_SECRET_KEY
   Value: полный sk_test_… из Stripe Sandbox
   ```

   Выберите **Production** и **Preview**, если хотите проверять оба вида развёртываний. Production в Vercel означает опубликованный адрес сайта; Stripe при этом остаётся в тестовом режиме.
4. Нажмите **Deploy**. Если ключ добавлен после первой публикации: **Project Settings → Environment Variables**, сохраните его, затем **Deployments → последнее развёртывание → Redeploy**. Изменение переменных действует только на новые развёртывания.
5. Откройте опубликованный сайт и нажмите **Stripe test**. Появится официальный Stripe Checkout для тестового платежа **USD 1.00**. Введите официальный тестовый номер из документации Stripe и завершите сценарий. После возврата результат проверяется сервером и показывается с платёжной системой и последними четырьмя цифрами.

Публичный ключ `pk_test_…` здесь не нужен: используется переход на Stripe-hosted Checkout. Секретный ключ остаётся в функциях Vercel, не в HTML или браузерном JavaScript. Ключи live-режима отклоняются.

## Как проверить

Откройте `/api/stripe/config` на своём домене: при заданном тестовом ключе ответ содержит `configured: true` и `mode: "test"`. Это проверяет наличие и формат ключа. Правильность ключа и разрешений подтверждается созданием Checkout после нажатия **Stripe test**.

`Format OK` относится к префиксу платёжной системы, длине, Luhn, дате и формату CVV. Это не подтверждение существования банковской карты. Генерируемые строки не отправляются в Stripe. Stripe Sandbox предназначен для официальных тестовых данных и не проверяет активность реальных карт.

## Локальный запуск и проверки

Установите Node.js 24. Дополнительных пакетов нет. Для локального Stripe скопируйте `.env.example` в `.env` и вставьте свой тестовый ключ после `=`. В терминале из корня проекта:

```text
node --env-file-if-exists=.env scripts/dev-server.mjs
```

Откройте http://127.0.0.1:4180/. После изменения локального `.env` перезапустите сервер. Запуск автоматических проверок без обращения к вашему аккаунту Stripe:

```text
node --test test/*.test.mjs
```

На Vercel вход через ChatGPT не используется. Сеанс Stripe привязан к подписанной HTTP-only cookie этого браузера на сутки; после оплаты возвращайтесь в том же браузере на тот же домен. При смене ключа прежние сессии браузера становятся недействительны. Это изоляция браузерных тестов, не система аккаунтов. Ограничение частоты в памяти действует в пределах одного серверного экземпляра.

Архив подготовлен и проверен локально с имитацией ответов Stripe; публикация в вашем Vercel и платёж через ваш Stripe ещё не выполнялись. Реальная выдача товара/услуги требует отдельного процесса заказов и проверенных вебхуков.
